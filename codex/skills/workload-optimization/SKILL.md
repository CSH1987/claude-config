# Codex 작업량 최적화

## 역할별 배치

- `top`: 방향·아키텍처·최종 종합. 현재 Codex의 최상위 추론 모델과 high 이상을 쓴다.
- `mid`: 정해진 기준의 검증·리뷰·판정. 균형형 모델과 high 이상을 쓴다.
- `exec`: 확정된 명세의 구현·변환. 균형형 모델과 medium 이상을 쓴다.
- `explore`: 파일 목록·대량 검색·로그 정리. 빠른 모델과 medium을 쓴다.
- 모델 이름이 바뀌면 문자 그대로 복사하지 말고 같은 능력 역할로 다시 매핑한다. 모호하면 한 단계 올린다.

현재 기본 매핑은 `top=GPT-5.6 Sol`, `mid/exec=GPT-5.6 Terra`, `explore=GPT-5.6 Luna`다. 계정에서 사용할 수 없는 모델이면 상속 모델로 실행하고 그 사실을 보고한다.

Codex 네이티브 역할 파일은 `architect`(top) · `reviewer`(mid) · `executor`(exec) · `explorer`(explore)다. 역할이 분명하면 같은 이름의 custom agent를 우선 사용한다. 메인 세션의 전체 바이패스 권한을 탐색·검토에 그대로 쓸 필요가 없으므로 `architect`·`reviewer`·`explorer`는 읽기 전용으로 실행한다.

직접 시작하는 저비용 세션은 `codex --profile routine`(반복 구현) 또는 `codex --profile explore`(대량 탐색)를 쓴다. 전체 바이패스를 잠시 끄려면 `codex --profile safe`를 쓴다.

## 컨텍스트 전달

- 독립적인 대량 조사에는 `fork_turns="none"` 또는 필요한 최근 턴만 전달한다.
- 사용자 결정·숨은 제약이 중요한 판단 작업만 전체 맥락을 전달한다.
- 큰 로그와 조사 원문은 파일에 저장하고, 메인 에이전트에는 결론·근거·경로만 돌려준다.
- Vault 원문은 동기화 범위에서 빼지 않는다. 전체 지도를 먼저 확인한 뒤 질문과 관련된 원문을 직접 읽는다.

## 복잡한 작업

고위험 작업에만 `설계(top) → 검증(mid) → 구현(exec) → 실제 테스트` 순서를 쓴다. 검증 반려 뒤 재설계는 최대 두 번이다. 작은 작업은 단일 에이전트로 끝낸다.

## 압축·복구

압축 시 다음 네 항목을 우선 보존한다.

1. 현재 상태와 다음 단계
2. 변경한 파일과 핵심 내용
3. 테스트 결과와 실패 원문 경로
4. 사용자가 확정한 결정과 이유

압축 뒤 SessionStart가 Vault 전체 지도와 `10_컨텍스트` 패턴을 다시 넣는다. transcript 내부 형식은 안정 계약이 아니므로 훅에서 파싱하지 않는다.

## 측정과 복귀

- Claude 비용 수치를 Codex 수치로 간주하지 않는다. Codex에서 모델·역할·반려·재작업을 따로 측정한다.
- 표본 5건 이상에서 반려율이 50% 이상이거나 3건 연속 반려되면 한 단계 높은 역할로 복귀를 제안한다.
- 전역 토큰 제한이나 자동 압축 시점을 근거 없이 고정하지 않는다. 변경 전후 품질·토큰을 비교한 뒤 확대한다.
- 자동 라우팅 변경은 하지 않는다. 측정 결과와 제안만 만들고 사람이 승인한 뒤 적용한다.
